# 按句读 · 阅读辅助

**读论文时最常见的卡顿，是「每个词都认识，连起来不知道在说什么」。这一句卡住了，后面的论证就全跟不上了。**

这个扩展解决这一件事：把网页和 PDF 按句切开、逐句高亮，读到读不懂的那一句**按一下空格**，就地给出这一句的讲解 —— 主干是什么、术语什么意思、结构难在哪。原文继续高亮着，不用来回切换。

**已上架 Microsoft Edge 加载项商店（v1.0.0）：**
<https://microsoftedge.microsoft.com/addons/detail/npbppgdpikakaldohlglkccjfomfkoob>

> 商店搜索对新扩展有索引延迟，刚上架时搜不到是正常的 —— **用上面的直链**。

## 它最特别的地方：不编造

市面上不少 AI 阅读工具会在你还没问的时候，就信心十足地给你一段解释。问题是：**你没法判断那是原文的意思，还是它自己编的。**

所以这个扩展在几个地方刻意**少做一点**：

| 做法 | 为什么 |
|---|---|
| 术语译名只采用外部查证结果（你的术语表 > Wikipedia） | 查不到就只给英文原词和意思说明，**不会给你编一个中文名** |
| 模型自己写的「某某 = 某某」**一律丢弃** | 实测中它编出过 `OpenCV = 奥克拉夫视网膜`，这种东西不该出现在学习工具里 |
| 拿不准时允许它写「这句我不确定」 | 承认不确定，比编一个像样的答案有用 |
| 每条术语都标出来源 | `✓ 你的术语表` / `✓ 外部查证` |

**这几条不是想出来的，是从访谈里长出来的** —— 见 [`INTERVIEW.md`](INTERVIEW.md)。

## 怎么用

**键盘：**

| 键 | 作用 |
|---|---|
| `空格` | 讲解当前这一句（自动带上前后文） |
| `←` `→` | 上一句 / 下一句 |
| `↑` `↓` | 调阅读速度（0.5 一档，2~15；↑ 变慢） |
| `H` | 显示 / 隐藏讲解侧栏 |
| `0` | 清掉记住的阅读速度，下次重新测 |

**速度不用一开始就调对。** 它会一边读一边测你的节奏，觉得快慢就按 ↑↓，它会重新学。

## 前史：同一时期的另一条路

这个扩展之前，我在做另一个问题：**用普通摄像头做免手交互**（视线 / 指尖），想让人读论文时手不用离开键盘。那份研究测了五种模态的精度边界，最后得出一条结论：

> 决定可用性的不是绝对精度，而是「活动范围 / 抖动」这个比值。

**那是另一个问题** —— 研究的是「用什么操作电脑」（输入方式），这个扩展解决的是「哪一句没读懂」（理解内容）。**两者没有代码依赖，也没有共用技术。**

那部分单独放在另一个仓库：**<https://github.com/guizhouxiemeng/gaze-precision-study>**

> 唯一的共同点是同一个出发点：读论文时不顺畅。
> [`JOURNEY.md`](JOURNEY.md) 里有从那边转到这边的原因。

## 工程做法

这个项目**单靠一个人、没有 CI、没有测试框架**，但要求自己每次改动都能验证。所以长出了一套自己的工具：

**① 一条命令跑完全部校验**

```bash
python tools/verify_all.py
```

13 项：单元测试、契约测试、JS/Python 语法、**包与源码逐字节一致**、商店文案长度限制、隐私政策与 manifest 的一致性。**全过才允许交付。**

**② 快照系统 —— 因为我没有版本控制**

```bash
node tools/snap.js save "改了什么"
node tools/snap.js diff      # 看差异
node tools/snap.js restore   # 回滚
```

**这不是"没有 git 的替代品"，它解决的是另一个问题**：改坏了自己知道回哪去。

**③ 作用域检查器 —— 用缩进推断嵌套，不解析语法**

```bash
node tools/scope-check.js
```

起因是同一类 bug 反复出现：`const X = (() => { ... })()` 这样的模块里，**里面的东西外面看不到**。两个模块互相看不见，静态分析不出来的话，只能等运行时 `ReferenceError`。

试过括号匹配 —— **失败了三次**（注释、字符串、正则字面量里的括号都会骗过它）。最后改用缩进推断，因为**这个代码库的缩进是可靠的，而括号不是**。

> 第三项检查**故意做成"仅供参考、不让校验失败"**。因为它误报多，而**会误报的检查比没有更糟** —— 报一堆假的，真的那条就淹在里面，然后人会开始忽略整个检查。

**④ 打包自检**

`package.js` 会在打包后自己读回包来验：manifest 引用的文件是否都在、`__MSG_` 占位是否都有文案、**商店文案是否超长**。最后一条是被商店拒过一次之后加的：

```
The translation for field Description in locale en is too long …
exceeds maximum size limit of 190 characters   （当时写了 212）
```

**⑤ 版本可追溯**

界面显示版本号；打包时打印构建标记；校验会比对**包内那个文件的构建标记**和当前源码是否一致 —— **"改了代码忘了重新打包"会被自动拦下**。这条是被同一个错误绊了三次之后加的。

## 怎么跑起来

**装扩展（推荐）**：从[商店](https://microsoftedge.microsoft.com/addons/detail/npbppgdpikakaldohlglkccjfomfkoob)装。

**从源码加载：**

```
① 打开 edge://extensions，开启「开发人员模式」
② 点「加载解压缩的扩展」，选择本仓库的 plugin/ 目录
```

**不用装扩展，直接试**：用浏览器打开 `demo/reader_flow.html`。

**改完源码要同步**（`plugin/reader_flow.js` 从 `demo/reader_flow.html` 生成）：

```bash
python tools/sync_plugin.py
python tools/verify_all.py
```

**讲解从哪来（三种后端，自己选）：**

| 后端 | 费用 | 内容去向 |
|---|---|---|
| 浏览器内置模型 | 免费 | **不出本机**。需要 Edge/Chrome 138+ 并开启实验室功能 |
| 本地 Ollama | 免费 | **不出本机** |
| 任意 OpenAI 兼容 API | 自付 | 发给你选择的那个服务商，扩展本身不经手 |

默认是内置模型。**如果那个实验室开关没打开，侧栏会给出开启步骤，而不是只丢一句报错。**

## 已知限制

- **扫描版 PDF（纯图片）读不了**，会明确提示。需要 OCR，这个版本不做。
- **浏览器内置模型能力有限。** 同一句可以点卡片上的 ⟳ 重新生成，结果会不一样 —— 小模型的固有特性，不是 bug。
- **免费路线依赖浏览器实验性功能**，厂商随时可能改动。
- **推断层（判断你卡在哪句）已降级为辅助信号**，不作为主要依据。实测它并不比数句子长度更好，详见 [`FINDINGS-trigger.md`](FINDINGS-trigger.md)。

## 隐私

不收集任何个人数据。**没有自己的服务器。**

只有你主动按空格时，那一句正文才会发给你自己配置的服务。术语查证只发送术语本身，不发送句子。

完整政策：<https://guizhouxiemeng.github.io/sentence-reader-privacy/>
