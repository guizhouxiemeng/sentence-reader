# 自适应阅读辅助 · 浏览器插件

按句高亮文章，读不懂按 <kbd>空格</kbd>，就地给出结合上下文的讲解。
**原文上同步高亮当前句**，段落结构与页面排版完全保持原样。

## 为什么必须是插件

普通网页受**同源策略**限制，读不到别的网站的内容。只有扩展能在
**目标页面的上下文里**直接操作 DOM，所以能：

- 拿到**渲染完成后**的真实文字（动态站点也能取）
- 把高亮**直接加在原文上**，段落结构保持原样
- 不需要服务器代理，也没有跨域问题

## 安装（开发模式）

1. **同步阅读界面**（网页版与插件版共用一份实现）：

   ```
   python tools/sync_plugin.py
   ```

2. 打开 `edge://extensions` 或 `chrome://extensions`，开启右上角 **开发人员模式**

3. 点 **加载解压缩的扩展** → 选择 `gaze-project/plugin` 目录

4. 打开一篇文章页 → 点工具栏上的扩展图标 → 页面右下角浮出阅读面板

## 用法

| 操作 | 作用 |
|---|---|
| <kbd>空格</kbd> | 第一次：暂停 + 讲解当前句；第二次：继续，并从下一句往下读 |
| <kbd>←</kbd> <kbd>→</kbd> | 手动上/下一句（原文高亮跟着走） |
| <kbd>↑</kbd> <kbd>↓</kbd> | 调速度（每句 1.2~10 秒） |
| <kbd>H</kbd> | 隐藏/显示侧栏 |
| 关闭 | 移除浮层，原文高亮一并清除 |

侧栏里的 **API 设置**：key 只存本机 `localStorage`，不上传任何服务器。
支持 DeepSeek / OpenAI / 通义千问 / Kimi / 任意 OpenAI 兼容接口。
**留空则使用占位讲解**（界面与触发逻辑照常可用）。

## 文件结构

| 文件 | 职责 |
|---|---|
| `manifest.json` | MV3 清单 |
| `background.js` | 转发消息：取正文 / 打高亮 / 开浮层 |
| `content.js` | 注入页面：提取正文、原文高亮、浮层界面（Shadow DOM 隔离） |
| `panel.html` + `panel.js` | 侧栏外壳（兜底路径，正常走页面浮层） |
| `reader_flow.html` + `reader_flow.js` | 阅读界面（**由 sync_plugin.py 从 demo/ 同步生成，勿手改**） |

## 推进速度：按句长算，并随你的纠正自适应

固定间隔（"每句 N 秒"）有个根本问题：长句太短、短句太长，
而且这样测出来的"停留时长"恒等于 N，**没有任何信息量**。
所以改成：

```
本句给的时间 = 本句的【阅读单位数】/ 速度 × 1.15
```

**"阅读单位"按语言分别计数**（这一条踩过坑）：

| 内容 | 算作 |
|---|---|
| 中文字符 | 1 字 |
| 英文字母串（`architectures`） | **1 词** |
| 空格、标点 | 不计 |

> 早先直接用 `text.length`：空格被算进字数，英文按**字母数**算 ——
> "architectures" 有 13 个字母被当成 13 个字，于是英文长句被给了 2~5 倍的时间。
> 实测偏差见 `tools/test-units.js` 的对照表（英文长句 +373%）。

**速度从你的手动纠正里学**：

| 你的动作 | 系统推断 | 调整 |
|---|---|---|
| 按 `←` 退回上一句 | 上一句给的时间不够 | 速度 ×0.90（调慢） |
| 计时未到就按 `→` | 给多了 | 速度 ×1.04（调快） |

**这也让推断层重新有了有效信号**：退回次数正是设计文档里的"回看次数"。
（自动推进模式下"停留时长"恒等于系统给的时间，时间路失效，
所以受阻判定留了操作路：**退回 ≥ 2 次即判受阻**。）

## 架构：五模块，高内聚低耦合

```
① TextSource   文本 → 句子数组        ← 插件只替换这一个的数据来源
② Reader       高亮推进 + 键位
③ Trigger      判断"该不该讲解"        ← 未来接停留时长推断层的入口
④ Explainer    建 prompt + 调 LLM + 缓存（加技能的地方）
⑤ SidePanel    显示讲解卡片
```

加新技能（代码解释、教材辅导等）**只需在 `Explainer.SKILLS` 里加一项**，
其余四个模块不动。

## 实现要点（都是踩过的坑）

### 1. 界面必须和扩展同源

早先用 `<iframe src="http://127.0.0.1:8765/...">`，那个 iframe 的来源是
本地服务器而非扩展，**`chrome.*` 是 undefined**，一调用就崩。
现在浮层由 content script 注入，天然在页面上下文里。

### 2. MV3 禁止内联脚本

```
Executing inline script violates the following Content Security Policy
directive 'script-src 'self''
```

所以 `sync_plugin.py` 会把内联 `<script>` 抽成外部 `.js`。
比在 manifest 里开 `'unsafe-inline'` 更安全，商店审核也不会卡。

### 3. 高亮用文本匹配，不用编号

**这是最关键的一次重构。** 早先面板传"段落号"、页面存"标记值"，
两套编号在交界处反复错位，连续改了四次都没稳定：

| 尝试 | 结果 |
|---|---|
| background 转发时漏传 `text` | 句子文本为空 |
| 把句子号当段落号传 | 偏移一段 |
| 标题占用段落号 0 | 又偏移一段 |
| 用过滤后的数组下标当段落号 | 再偏移 |

根子在于"两个编号系统必须用同一个数"这个耦合本身。
**现在改成直接拿句子文本去原文里找**（开头 12 字相同 + 长度接近），
编号错位这一整类问题从此不存在。

### 4. 原文高亮只动文字节点

很多站点靠 JS 在元素上绑事件，**重建 DOM 会让页面交互失效**。
所以包裹时只切分文字节点（`<span class="rf-sent">`），不重建元素；
句子跨多个节点（中间夹链接、加粗）时退化为整块高亮。

### 5. 正文容器选"够长的最小容器"

早先取"第一个超过 600 字的候选"，经常选到外层大包裹，
把侧栏、相关阅读都算进正文（一篇技术文章提取出 106 段）。
现在取**字数 ≥800 且字数最小**的候选，语义化容器（`article`/`main`）
天然更具体会被优先选中。

### 6. 元素访问一律判空

扩展模式会替换部分 DOM（粘贴框等），代码若还去读那些元素就会崩：

```
TypeError: Cannot set properties of null (setting 'textContent')
```

现在 `msg()` 会自动降级建一个提示条，所有事件绑定走安全绑定
（缺元素就跳过并记一条 `console.warn`，不影响其余功能）。

## 权限说明

| 权限 | 用途 |
|---|---|
| `scripting` | 在目标页面注入 `content.js` |
| `tabs` | 读标签页列表（用于多标签时选择目标） |
| `activeTab` | 点图标时临时授权 |
| `sidePanel` | 侧栏兜底路径 |
| `host_permissions` | `http(s)://*/*` —— 读取网页正文必需 |

**`activeTab` 单独不够用**：它只在"点图标的那一瞬间"有效，而实际链路是
`点图标 → 激活面板 → 面板发消息 → 后台注入`，授权到注入时已经失效，
报错是 `Extension manifest must request permission to access this host`。
